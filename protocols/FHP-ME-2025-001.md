# Fair Hiring Protocol — Match Explanation Schema (Draft v1.0)

This is the transparency engine, the thing that makes the entire system trustworthy. 
If the `Candidate Profile` and `Job Brief` are the inputs, and the matching pipeline is the process, then the `Match Explanation` is the contract that proves the system behaved fairly.

We need clean, protocol grade JSON schema, but and explain the design choices as we go so we can clearly see how each part reinforces fairness.

This schema answers one question: *“Why did the system make this decision?”*

It must be:
- deterministic
- auditable
- human readable
- machine readable
- versioned
- complete

`match-explanation.schema.json`

# Why this schema is so powerful

## 1. It forces transparency

Every decision is broken down:
- skills
- constraints
- preferences
- bias correction
- scoring

Nothing is hidden.

## 2. It protects candidates

They can see:
- why they were rejected
- what they can improve
- whether bias was detected
- whether bias was corrected

This is unheard of in hiring today.

## 3. It protects companies

They get:
- clear reasoning
- structured evidence
- defensible decisions
- compliance ready logs

## 4. It protects the protocol

Every match is:
- versioned
- auditable
- reproducible

This prevents manipulation.

# Scoring + Bias Correction
Now that we have:
- Candidate schema
- Job schema
- Match explanation schema

We can define the scoring algorithm and the bias correction algorithm.

These two are the beating heart of fairness.

## A. Scoring
- must have logic
- nice to have weighting
- transferable skill compensation
- experience relevance
- preference alignment
- normalization

## B. Bias Correction
- demographic parity checks
- skew detection
- correction factors
- transparency rules
- drift monitoring
