# Candidates
The following is a clean, structured breakdown of what belongs in a **Fair Candidate Profile**, grounded in the **Fair Hiring Protocol** and designed to support transparency, semantic matching, and bias aware scoring.


## 1. Core Identity (Minimal, Candidate Controlled)

This is the absolute minimum needed for the system to function.
- 	Name (or pseudonym if anonymous mode is enabled)
- 	Contact method (email or relay)
- 	Location preference (not home address)
- 	Work authorization constraints (optional)
- 	Visibility settings (who can see what)

Fairness principle: Identity should never be used in matching — only in communication.

## 2. Skills (The Heart of the Profile)

This is where the system becomes radically fairer than traditional CVs.

### 2.1. Self Declared Skills
- 	Primary skills
- 	Secondary skills
- 	Tools, frameworks, methodologies

### 2.2. AI Inferred Skills

From:
- 	CV parsing
- 	project descriptions
- 	work history
- 	portfolio items

Candidates must be able to:
- 	confirm
- 	reject
- 	edit
- 	reorder

### 2.3. Skill Proficiency (Candidate Defined)

Not numeric (which invites bias), but categorical:
- 	“Confident”
- 	“Comfortable”
- 	“Learning”
- 	“Expert through experience”
- 	“Expert through formal training”

### 2.4. Transferable Skills
These are often the key to fairness:
- 	leadership
- 	communication
- 	problem solving
- 	mentoring
- 	stakeholder management
- 	cross functional collaboration

Fairness principle: Skills, not job titles, drive matching.

## 3. Experience (Structured, Not Narrative)

Traditional CVs are prose. A fair system needs structure.

### 3.1. Roles (Structured)

Each role includes:
- 	title (free text)
- 	responsibilities (structured list)
- 	skills used (structured)
- 	achievements (structured)
- 	impact (optional)
- 	duration (start/end)

### 3.2. Projects

Especially important for:
- 	career changers
- 	self taught candidates
- 	freelancers
- 	older workers with nonlinear paths

Each project includes:
- 	goal
- 	tools used
- 	outcomes
- 	skills demonstrated

### 3.3. Non Traditional Experience
- 	caregiving
- 	volunteer work
- 	open source contributions
- 	community leadership
- 	personal projects

Fairness principle: Experience ≠ employment history.

## 4. Preferences (Candidate First Matching)

This is where candidates regain agency.

### 4.1 Work Preferences
- 	remote / hybrid / onsite
- 	full time / part time / contract
- 	industries of interest
- 	company size preference
- 	team culture preferences

### 4.2. Role Preferences
- 	preferred titles
- 	preferred responsibilities
- 	preferred domains

### 4.3. Salary Expectations
- 	minimum acceptable
- 	preferred range
- 	negotiable or not

### 4.4. Career Goals

Optional but powerful:
- 	“I want to move into leadership”
- 	“I want to stay hands on”
- 	“I want to switch domains”
- 	“I want stability”
- 	“I want high growth environments”

Fairness principle: Matching is mutual — not one sided.

## 5. Constraints (Hard Filters That Are Fair)

These are the only filters companies are allowed to use.

### 5.1. Availability
- 	immediate
- 	2 weeks
- 	1 month
- 	specific date
### 5.2. Location Constraints
- 	willing to relocate
- 	not willing to relocate
- 	specific regions
### 5.3. Legal Constraints
- 	visa requirements
- 	work authorization
### 5.4. Schedule Constraints
- 	part time availability
- 	flexible hours
- 	fixed hours

*Fairness principle: Constraints are neutral — they don’t encode bias.*

## 6. Optional Demographic Data (Bias Monitoring Only)

This is never used in matching.

It is used only to:
- 	detect bias
- 	correct systemic skew
- 	ensure parity

Candidates can choose to provide:
- 	age range
- 	gender identity
- 	ethnicity
- 	disability status
- 	socioeconomic background
- 	education level

*Fairness principle: Protected attributes are used to protect, not to filter.*

## 7. Evidence Layer (Optional but Powerful)

This is where candidates can prove skills without relying on job titles.

### 7.1. Portfolio Items
- 	GitHub repos
- 	design portfolios
- 	writing samples
- 	case studies

### 7.2. Assessments (Optional)

Not pass/fail — but skill demonstrating:
- 	coding challenges
- 	writing tasks
- 	design tasks
- 	scenario based reasoning

## 7.3. References (Optional)

Structured, not free form:
- 	relationship
- 	context
- 	skills observed
Fairness principle: Evidence > prestige.

## 8. Candidate Narrative (Optional, Humanizing)

A short, structured narrative:
- 	what motivates them
- 	what they enjoy
- 	what they want next
- 	what environments they thrive in

This is not used for scoring — only for human understanding.

## 9. Candidate Rights (Embedded in the Profile)

This is where fairness becomes enforceable.

Candidates must be able to:
- 	see how they were matched
- 	see why they were rejected
- 	correct incorrect inferences
- 	hide sensitive data
- 	delete their profile
- 	export their data
- 	control visibility
- 	challenge unfair outcomes

This is the ethical backbone.

# Putting it all together

A fair candidate profile is:
- 	structured (for matching)
- 	semantic (for skill inference)
- 	candidate controlled (for autonomy)
- 	bias aware (for fairness)
- 	transparent (for trust)
- 	minimal (no unnecessary data)
- 	optional where sensitive (for safety)

*It’s the opposite of a CV. It’s a data model for fairness.*
